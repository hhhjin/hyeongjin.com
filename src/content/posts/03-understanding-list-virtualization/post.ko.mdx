가상화는 큰 리스트를 렌더링할 때 사용할 수 있는 가장 유용한 최적화 기법 중 하나입니다.

수천 개의 요소가 한 번에 DOM에 마운트되면 브라우저는 layout, painting, compositing에 훨씬 더 많은 시간을 써야 합니다. 이런 추가 작업은 스크롤을 버벅이게 만들고 전체 반응성도 떨어뜨릴 수 있습니다.

핵심 아이디어는 단순합니다. 사용자가 현재 볼 수 있는 것만 렌더링하는 것입니다. 즉, viewport 안에 들어온 행만 실제로 DOM에 마운트됩니다.

어려운 부분은 이렇게 최적화된 리스트가 여전히 일반 리스트처럼 느껴지게 만드는 일입니다. 사용자는 모든 행이 실제로 렌더링된 경우와 같은 스크롤바 크기와 스크롤 동작을 기대하기 때문입니다.

가상화된 리스트가 일반 리스트처럼 동작하려면 두 가지를 관리해야 합니다.

1. 전체 컨테이너의 크기 (전체 스크롤 높이를 흉내 내기 위해)
2. 현재 보이는 요소들의 절대 위치

viewport가 바뀔 때마다, 예를 들어 사용자가 스크롤할 때마다, 현재 스크롤 위치를 기준으로 어떤 행을 보여 줘야 하는지 다시 계산합니다.

이제 그 흐름을 하나씩 살펴보겠습니다.

---

## 전체 컨테이너 크기 추정하기

어떤 행이 보이는지 판단하기 전에, 스크롤 영역 자체가 모든 행이 이미 존재하는 것처럼 동작해야 합니다.

모든 아이템의 높이가 같다면, 이를 처리하는 가장 간단한 방법 중 하나는 다음과 같습니다.

1. 행의 예상 높이를 하나 정한다.
2. 그 값을 `items.length`와 곱한다.

이렇게 하면 아직 전체 리스트를 렌더링하지 않았더라도 전체 스크롤 높이를 미리 구할 수 있습니다.

이 방식은 mount 시점에 `getBoundingClientRect()`로 측정하는 것보다 더 좋은 출발점이 되는 경우가 많습니다. spacer의 크기를 즉시 정할 수 있어서 초기 layout shift를 피할 수 있기 때문입니다.

아래 예제에서는 `10,000`개의 아이템을 만들고, `estimatedItemHeight * items.length`로 spacer 높이를 계산합니다.

<MeasuredContainerExample />

```jsx
const items = Array.from({ length: 10000 }, (_, index) => ({
  id: index,
  label: `Item ${index + 1}`,
}))

const estimatedItemHeight = 48
const containerHeight = estimatedItemHeight * items.length

return (
  <div style={{ overflow: "auto", height: 500 }}>
    <div style={{ height: containerHeight }} />
  </div>
)
```

이 시점에서 브라우저는 이미 올바른 크기의 스크롤바를 보여 줄 수 있습니다. 보이는 행은 아직 마운트되지 않았지만, 컨테이너는 전체 리스트를 모두 렌더링했을 때와 같은 총 높이를 차지하고 있습니다.

추정값이 조금 빗나가더라도 나중에 실제 측정값으로 보정할 수 있습니다. 하지만 출발점으로서는 대개 추정값이 더 단순하고 안정적입니다.

이것이 가상화의 첫 번째 절반입니다. 먼저 전체 스크롤 공간을 유지하고, 그다음 viewport와 겹치는 행만 렌더링합니다.

## 어떤 행을 렌더링할지 결정하기

전체 스크롤 공간이 준비되면, 다음 단계는 어떤 행이 viewport와 겹치는지 계산하는 것입니다.

여전히 모든 아이템의 높이가 같다고 가정하고 있으므로, 각 행에 대한 측정 기록을 미리 계산해 둘 수 있습니다.

각 항목에는 다음 정보가 들어갑니다.

1. `key`: 그 행을 식별하는 안정적인 값
2. `start`: 그 행이 시작되는 위치
3. `end`: 그 행이 끝나는 위치
4. `size`: 그 행의 높이

실제 행 내용은 여전히 `items[index]`에서 가져오면 됩니다. 측정 기록에는 전체 스크롤 영역 안에서 그 행을 올바르게 배치하는 데 필요한 정보만 있으면 됩니다.

예를 들어 측정 리스트는 이렇게 만들 수 있습니다.

```jsx
const measurements = items.map((item, index) => {
  const start = index * itemHeight
  const end = start + itemHeight

  return {
    index,
    key: item.id,
    start,
    end,
    size: itemHeight,
  }
})
```

그다음 사용자가 스크롤할 때마다 viewport 범위를 이 테이블과 비교해서, 겹치는 행만 남깁니다.

```jsx
function getVirtualItems({ measurements, scrollTop, viewportHeight }) {
  const viewportStart = scrollTop
  const viewportEnd = scrollTop + viewportHeight

  const firstVisibleIndex = measurements.findIndex(
    (item) => item.end > viewportStart
  )

  let lastVisibleIndex = firstVisibleIndex

  while (
    lastVisibleIndex < measurements.length &&
    measurements[lastVisibleIndex].start < viewportEnd
  ) {
    lastVisibleIndex += 1
  }

  return measurements.slice(firstVisibleIndex, lastVisibleIndex)
}
```

이 부분이 가상화의 핵심입니다. 개념적으로는 전체 리스트가 여전히 존재하지만, `getVirtualItems()`는 지금 렌더링해야 하는 부분집합만 반환합니다.

## `scrollToIndex`로 특정 행으로 점프하기

모든 행에 대한 측정 기록이 생기면, 특정 인덱스로 점프하는 일도 단순해집니다.

그 행을 찾기 위해 DOM을 다시 뒤질 필요가 없습니다. `measurements[index].start`를 보면 전체 스크롤 컨테이너 안에서 그 행이 어디서 시작해야 하는지 이미 알고 있기 때문입니다.

그래서 최소한의 `scrollToIndex()`는 이렇게 생길 수 있습니다.

```jsx
function scrollToIndex(index) {
  const measurement = measurements[index]

  if (!measurement) return

  viewportElement.scrollTo({
    top: measurement.start,
    behavior: 'smooth',
  })
}
```

이것이 가상화 라이브러리들이 사용하는 핵심 아이디어와 같습니다. 측정 리스트에서 목표 행을 찾고, 그것을 스크롤 오프셋으로 바꾼 뒤, 스크롤 컨테이너를 이동시키는 것입니다.

아래 예제에서는 맨 위, 중간, 맨 아래, 혹은 원하는 임의의 인덱스로 점프해 보면서 새로운 스크롤 위치 주변의 가상화된 행이 어떻게 업데이트되는지 볼 수 있습니다.

실전에서는 보이는 행만 딱 렌더링하지는 않는 경우가 많습니다. 대부분의 구현은 viewport 앞뒤에 작은 `overscan` 버퍼를 추가해서, 화면 바로 바깥의 몇 개 행도 미리 마운트해 둡니다.

왜 그럴까요? 스크롤은 연속적이고 빠르게 일어나기 때문입니다. 행이 정확히 보이기 시작하는 순간에만 마운트되면, 빠르게 스크롤할 때 잠깐 빈 공간이 보이거나 콘텐츠가 조금 늦게 나타날 수 있습니다. `overscan`은 약간의 추가 DOM 작업을 들이는 대신 훨씬 더 부드러운 움직임을 얻는 방법입니다.

아이디어는 단순합니다.

```jsx
const overscan = 3

const startIndex = Math.max(0, firstVisibleIndex - overscan)
const endIndex = Math.min(
  measurements.length,
  lastVisibleIndex + overscan
)

return measurements.slice(startIndex, endIndex)
```

이 정도만으로도 꽤 괜찮은 첫 버전을 만들 수 있는 경우가 많습니다.

그리고 바로 여기서부터 실제 서비스의 가상화는 더 복잡해지기 시작합니다.

- 아이템 높이가 고정되어 있지 않다면, 하나의 정적인 측정 테이블을 계속 믿을 수 없습니다.
- 새 아이템이 삽입되거나 기존 아이템이 제거되면, 그 뒤에 오는 모든 행의 오프셋도 함께 업데이트해야 합니다.
- 이미지 로딩이나 콘텐츠 확장 때문에 렌더링 후 아이템 높이가 바뀌면, 그 행을 다시 측정하고 뒤따르는 위치도 모두 다시 계산해야 합니다.

결국 가상화의 기본 아이디어 자체는 단순합니다. 전체 스크롤 공간을 유지하고, 보이는 범위만 렌더링하고, 부드러움을 위해 약간의 `overscan`을 더하는 것입니다. 어려운 부분은 측정값 업데이트와, 리스트가 동적으로 변하기 시작할 때 나타나는 여러 edge case를 처리하는 데 있습니다.
