When a React component unmounts, its DOM is usually removed immediately.
So how can Motion still play an exit animation?

The key is that even after React decides a component is gone, `AnimatePresence` keeps rendering the exiting child just long enough for Motion to animate it out.
Only after that animation finishes is the child actually removed.

This post walks through that idea step by step.

### AnimatePresence

Why do we need `AnimatePresence`?
What happens if we leave it out?

<ExitPresenceComparison />

Without `AnimatePresence`, the `motion` node disappears from the tree as soon as `open` becomes `false`, so the `exit` transition never gets a chance to run.
The element simply vanishes.

That is why `AnimatePresence` matters.

---

What does `AnimatePresence` do?

Conceptually, it compares child keys between renders, keeps exiting children around for a little longer, and waits for their exit animations to finish.

Here is a minimal sketch of that idea:

```jsx
function AnimatePresence({ children }) {
  const presentKeys = children.map((child) => child.key)
  const [renderedChildren, setRenderedChildren] = useState(children)

  return (
    <>
      {renderedChildren.map((child) => {
        const key = child.key
        const isPresent = presentKeys.includes(key)

        const onExit = () => {
          // Remove this child from our list only after exit work is done.
          setRenderedChildren((prev) =>
            prev.filter((child) => child.key !== key)
          )
        }

        return (
          <PresenceChild
            key={key}
            isPresent={isPresent}
            onExitComplete={onExit}
          >
            {child}
          </PresenceChild>
        )
      })}
    </>
  )
}
```

The important part here is the idea, not the exact implementation:

`AnimatePresence` keeps its own list of rendered children, tells each child whether it is still present through `isPresent`, and removes it only after the child reports that its exit work is done.

Now let's look at a simplified `PresenceChild`:

```jsx
const PresenceContext = createContext(null)

function PresenceChild({ children, isPresent, onExitComplete }) {
  // childId → has this motion node finished exiting? (false until done)
  const presenceChildren = useMemo(() => new Map(), [])

  const context = useMemo(() => {
    return {
      isPresent,
      register: (childId) => {
        presenceChildren.set(childId, false) // not complete yet
        return () => presenceChildren.delete(childId) // unregister on unmount
      },
      onExitComplete: (childId) => {
        presenceChildren.set(childId, true)

        // Wait for every registered descendant before notifying AnimatePresence.
        for (const isComplete of presenceChildren.values()) {
          if (!isComplete) return
        }

        onExitComplete()
      },
    }
  }, [isPresent, onExitComplete, presenceChildren])

  return (
    <PresenceContext.Provider value={context}>
      {children}
    </PresenceContext.Provider>
  )
}
```

`PresenceChild` acts as the boundary for a single exiting subtree.

Its job is not to manage every detail of the lifecycle, but to coordinate exit completion within that subtree.
If multiple `motion` nodes inside it need time to finish exiting, `PresenceChild` waits until all of them are done before telling `AnimatePresence` that the whole child can be removed.

That state is passed down through `PresenceContext`.

```jsx
function MotionDiv({ children, exit }) {
  const id = useId()
  const { isPresent, register, onExitComplete } = useContext(PresenceContext)

  useEffect(() => {
    return register(id) // register with PresenceChild; cleanup unregisters
  }, [])

  useEffect(() => {
    if (!isPresent) {
      // Parent marked us leaving — run exit, then report completion
      exitAnimation().then(() => onExitComplete(id))
    }
  }, [isPresent])

  return <div>{children}</div>
}
```

This is heavily simplified, but it captures the core idea:

- the `motion` node registers itself with the surrounding presence boundary
- when `isPresent` becomes `false`, it starts its exit animation
- when that animation finishes, it reports completion
- once every registered node has finished, `AnimatePresence` can finally remove the child

A lot of real implementation details are omitted here, but this is the core idea that makes exit animation possible in React.
